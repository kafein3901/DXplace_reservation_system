## 1. 目的

学校のDXプレイスにある3Dプリンタと高性能PCを、予約によって公平に、かつ無駄なく使えるようにするWebシステム。学校側の要件は次の4つ。

1. 空きが、ひと目でわかる
2. 見た人が、使いたいと思える
3. 予約しないと使えない仕組みになっている
4. 使わなくなったら、必ずキャンセルされる仕組みになっている

## 2. 前提と制約

| ID     | 内容                                                                                                                                                                                                                 |
| ------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| PRE-1  | 利用者は全学年の生徒と教員。手続きの手軽さを厳密さより優先し、利用者の厳密な本人確認はしない。利用者が入力する学籍番号・名前や、操作（利用開始など）の自己申告は信頼する                                             |
| PRE-2  | ランニングコストは0円。利用が増えても費用が発生しない。無料の範囲を超えた場合は、費用が発生するのではなくシステムが停止する構成とする                                                                                |
| PRE-3  | 利用者は手持ちのスマートフォンやPCのブラウザで使う。アプリのインストールを必要としない                                                                                                                               |
| PRE-4  | 外部のサービスに利用者の個人情報（氏名、学籍番号など）を置いてよい                                                                                                                                                   |
| PRE-5  | 開発と保守は生徒が行う。一般的なWebの知識（HTML / CSS / JavaScript）を持つ生徒が理解し、引き継げること                                                                                                               |
| PRE-6  | Webシステムだけでは機器の物理的な利用を強制できない。学校側の要件3と4は、PRE-1の信頼のもとで実質的に満たす                                                                                                           |
| PRE-7  | 学校が配布しているアカウントとは連携できない。学籍番号は利用者が自分で入力する                                                                                                                                       |
| PRE-8  | 校内関係者による悪意ある操作は想定しない。セキュリティ上の対策は、校内関係者以外（外部）に対するものを対象とする                                                                                                     |
| PRE-9  | 長期休暇（最長約6週間）のあいだ利用がなくても、休暇明けにそのまま使える（NFR-5）                                                                                                                                     |
| PRE-10 | システムが使えない間も、機器の利用は止めない（その間は予約なしで使ってよい）                                                                                                                                         |
| PRE-11 | システムが使う外部サービスの管理権限は、学校（教員）が管理するアカウント（以下「学校のアカウント」）が持つ。開発・保守を行う生徒には、そのアカウントから権限を付与する。生徒の卒業や交代によってシステムが失われない |

## 3. 利用者と権限

### 3.1 利用の開始（一般の利用者）

| ID    | 要件                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| ----- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| USR-1 | 校内関係者とは、校内で共有された情報（以下「共有された情報」）を知っている者をいう。校内関係者以外は、システムを利用できない。画面を経由しない方法でも、データを読み書きできない。共有された情報の確認は、利用者の端末側ではなくサーバ側で行う                                                                                                                                                                                                                                                                                                              |
| USR-2 | 共有された情報を入力すると利用を始められる。同じ端末では、ADM-3で止められるまで再入力しなくてよい。共有された情報が未設定（ADM-3）の間は、誰も利用を始められない                                                                                                                                                                                                                                                                                                                                                                                            |
| USR-3 | 生徒か教員かを選び、学籍番号と名前（生徒は期生も）を入力して、利用者として操作する。別の人に切り替えられる。v0.1.0 では、入力内容を端末に保存しない。画面を開いている間だけ保持し、開き直したら入力し直す（端末に覚えさせる機能は後から加える）                                                                                                                                                                                                                                                                                                             |
| USR-4 | 学籍番号の形式と識別（下記）                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| USR-5 | 名前は、前後の空白を除いて1文字以上30文字以下とし、これに合わないものを受け付けない。空白だけのもの、改行や制御文字を含むものは受け付けない                                                                                                                                                                                                                                                                                                                                                                                                                 |
| USR-6 | 生徒は期生を持つ。期生は1以上の整数とし、これに合わないものを受け付けない。教員は期生を持たない                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| USR-7 | 名前は利用者（USR-4）ごとに1つ持つ。予約や利用には、その利用者に現在結びついている名前を表示する。名前・期生は、登録かログインをした利用者が、名前・期生の変更の画面で自分の分だけを変更できる。それまでと異なれば新しい名前に置き換え、置き換えたことを記録する（当時の名前は、この記録からたどれる）。登録・変更のほかの操作（ログインを含む）では置き換えない。期生も同じ扱いとする。v0.1.0 には本人確認がないため、他の利用者の学籍番号でログインすれば、その利用者として操作でき、名前・期生も書き換えうる。これはベータ版として承知のうえの制約である |

**USR-4 学籍番号**

- 生徒：8桁の数字。
- 教員：半角の英数字・ハイフン・ドット・アンダースコアからなる、1文字以上64文字以下の文字列。数字だけのものもある。
- USR-3で選んだ側の形式に合わないものは受け付けない。
- 利用者は「生徒か教員かの区別」と「学籍番号」の組で識別する。選び間違えると別の利用者になるが、これは承知のうえの制約である。
- 先頭の0も桁に数え、省いたものは受け付けない（先頭の0の有無が違えば別の学籍番号）。
- 全角で入力された文字は、半角の同じ文字として扱う。英字の大文字と小文字の違いは、同じ学籍番号として扱う。
- 名前は表示のためのもので、識別には使わない。RSV-4の「1人」、RSV-7〜RSV-11の「自分の」「本人」は、この識別による。

### 3.2 管理者

| ID    | 要件                                                                                                                                                          |
| ----- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ADM-1 | 利用者には一般の利用者と管理者の2種類がある。管理者の機能は管理者だけが使える。管理者のアカウントでは予約や利用の操作はできず、それらは一般の利用者として行う |
| ADM-2 | 管理者のアカウントと認証（下記）                                                                                                                              |

**ADM-2 管理者のアカウントと認証**

- 管理者は、IDとパスワードで認証でき、認証した状態を解ける。
- 管理者の認証は利用者とは入口を分け、共有された情報による利用の開始（USR-2）を前提としない（USR-1の例外。管理者は個別の認証だけで確認する）。ADM-3は、管理者の認証した状態を止めない。
- アカウントは、IDと表示用の名前（条件はUSR-5と同じ）を持つ。学籍番号は結びつけない。IDの形式は設計で定める。
- IDは管理者どうしで重複せず、削除したアカウントのIDは再び使えない（記録の上で別の人と区別がつかなくなるため）。
- 管理者は、管理者のアカウントを作成・削除でき、管理者の一覧を確認できる。自分自身のアカウントも削除できる。最後の1人の管理者は削除できない。
- パスワードを忘れた場合は、他の管理者が設定し直せる（IDは変わらない）。
- アカウントの削除とパスワードの設定し直しは、そのアカウントの認証した状態を、すべての端末で直ちに止める。
- パスワードの持ち方はSEC-4による。
- 学校のアカウント（PRE-11）は、システムの外から管理者のアカウントを作成し、パスワードを設定し直せる。最初の管理者はこの方法で作り、管理者の全員が認証できなくなった場合もこの方法で復旧する。学校のアカウントがシステムの外で行う操作は、記録（LOG-4）の対象としない。
- v0.1.0 には、管理者が自分のパスワードと表示用の名前を変更する機能がない。そのため、アカウントを作成した、またはパスワードを設定し直した管理者が、そのパスワードを知ったままになる。また、表示用の名前は作成後に変えられない。これらは承知のうえの制約である。

### 3.3 共有された情報の設定と変更

| ID    | 要件                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| ----- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| ADM-3 | 管理者は共有された情報を設定・変更できる。共有された情報は、最初は未設定とし、管理者がこの操作で設定するまで誰も利用を始められない（最初の設定も、変更と同じくLOG-4により記録する）。管理者が共有された情報を変更すると、変更前の情報による利用は、すでに利用を始めている端末も含めてすべての端末で止まる。確保済みの予約は変わらない。止まった後、校内関係者は新しい共有された情報によって再び利用できる。共有された情報の持ち方はSEC-4による（管理者も現在の値をシステムから確かめることはできない。わからなくなったら、この操作で設定し直す） |

## 4. 時刻の扱い

| ID    | 要件                                                                                                                                                                                                                   |
| ----- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| TIM-1 | 時刻に関わる判定は、利用者の端末の時計に左右されない。時刻は日本時間で扱う                                                                                                                                             |
| TIM-2 | 時間の範囲（予約の時間帯、猶予など）は、すべて開始の時刻を含み、終わりの時刻を含まない。10:00に終わる予約と10:00に始まる予約は重ならない                                                                               |
| TIM-3 | 時間帯の境界は分単位とする。開始時刻と終了時刻は1分単位で指定できる                                                                                                                                                    |
| TIM-4 | システムが現在時刻から境界を決める場合は、秒を切り捨てる。対象は、予約なしの利用の開始（RSV-17）、開始時刻より前の利用開始による開始（RSV-15）、利用を終了させる操作による終了時刻（RSV-18、MNG-3）である              |
| TIM-5 | 操作の記録の時刻は、実際の時刻のまま（秒を切り捨てない）とする                                                                                                                                                         |
| TIM-6 | 現在時刻との比較は、すべて秒を切り捨てた現在時刻で行う。新たに指定する時刻と変更する時刻について、開始時刻は現在時刻以降、終了時刻は現在時刻より後とする（RSV-5、RSV-9、RSV-10、RSV-17）。変更しない時刻には適用しない |
| TIM-7 | 終了時刻が開始時刻より後であることは、確保と変更の時点の条件である。利用を終了させた結果、時間帯の長さが0になること（同じ分のうちに始めて終えた場合）は認める                                                          |
| TIM-8 | 開室時間の概念は設けない。深夜や休日の時間帯も確保できる                                                                                                                                                               |

## 5. 予約と利用のルール

### 5.1 予約の状態

| ID    | 要件                                                                                                                                                                                                                       |
| ----- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| RSV-1 | 予約（予約なしの利用を含む）は、下の表のいずれかの状態をとる。時間帯を確保しているのは「予約済」と「利用中」だけで、それ以外の状態になった時点で時間帯は解放される。重複の判定（RSV-3）は、この2つの状態の予約を対象とする |

| 状態             | 意味                                                             |
| ---------------- | ---------------------------------------------------------------- |
| 予約済           | 時間帯を確保し、まだ利用を始めていない                           |
| 利用中           | 利用開始の操作をした（予約なしの利用は、始めた時点からこの状態） |
| 終了             | 利用を終えた（本人の操作、または終了時刻の経過による）           |
| 取消             | 本人が利用開始前に取り消した                                     |
| 無断不使用       | 猶予のうちに利用開始の操作がなかった                             |
| 管理者による取消 | 管理者が利用開始前に取り消した（機器の削除によるものを含む）     |
| 管理者による終了 | 管理者が利用中に終了させた                                       |

### 5.2 確保

| ID    | 要件                                                                                                                                                                                                                                                                                                                                                  |
| ----- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| RSV-2 | 予約は、機器ごとに、任意の開始時刻と終了時刻で指定した時間帯を確保するものである                                                                                                                                                                                                                                                                      |
| RSV-3 | 同じ機器について、時間帯が重なる予約は確保できない（同じ人の予約どうしを含む）。複数の人がほぼ同時に確保しようとした場合も同様。この制限は機器ごとのもので、別の機器であれば、同じ人が同じ時間帯に予約・利用できる                                                                                                                                    |
| RSV-4 | 確保は先着順。1人が同時に確保できる予約の件数には上限がある                                                                                                                                                                                                                                                                                           |
| RSV-5 | 機器、開始時刻、終了時刻を指定して予約を確保できる。終了時刻は開始時刻より後とする。どれだけ先の時間帯でも確保できる。件数の上限（RSV-4）には、予約済と利用中の予約を数える。予約なしの利用（RSV-17）で始めたものは数えない                                                                                                                           |
| RSV-6 | 1件の予約の時間帯の長さには上限がある。上限は全機器で共通の1つの値とする。予約の確保、予約なしの利用（RSV-17）、時間帯の変更（RSV-9、RSV-10。ただしRSV-12による）、開始時刻より前の利用開始（RSV-15）のすべてに適用する。この上限は入力の誤りを防ぐためのもので、利用の公平さを保つためのものではない。同じ人が同じ機器を続けて確保することは妨げない |

### 5.3 取消と変更

| ID     | 要件                                                                                                                                                                                                                                         |
| ------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| RSV-7  | 自分の予約済・利用中の予約を一覧できる                                                                                                                                                                                                       |
| RSV-8  | 予約した本人は、利用開始前（予約済）であれば自分の予約を取り消せる。取り消した時間帯は直ちに解放される                                                                                                                                       |
| RSV-9  | 自分の予約済の予約の時間帯（開始時刻・終了時刻）を変更できる。機器は変更できない（変えたい場合は、取り消して確保し直す）                                                                                                                     |
| RSV-10 | 自分の利用中の予約について、終了時刻を延長・短縮できる                                                                                                                                                                                       |
| RSV-11 | 時間帯の変更の条件：開始時刻を変更する操作は、変更前の開始時刻になる前にだけできる。終了時刻を変更する操作は、変更前の終了時刻になる前にだけできる。変更後の時刻を現在より前にすることはできない（TIM-6）。変更後の時間帯にもRSV-3を適用する |
| RSV-12 | 時間帯の変更は、件数（RSV-4）を理由には断らない。長さ（RSV-6）は、変更後の長さが上限以下であるか、変更前の長さ以下であれば受け付ける                                                                                                         |

### 5.4 利用

| ID     | 要件                                                                                                                                                                                                                                                                                                                      |
| ------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| RSV-13 | 予約した人が開始時刻から猶予のうちに利用開始の操作をしなかった場合、その予約は「無断不使用」となり、時間帯は自動で解放される                                                                                                                                                                                              |
| RSV-14 | 自分の予約について利用開始の操作ができる。RSV-15の条件を満たせば、開始時刻より前でもできる                                                                                                                                                                                                                                |
| RSV-15 | 利用開始の操作は、開始時刻より前でもできる。ただし、現在時刻から開始時刻までの間に、同じ機器を確保している他の予約がない場合に限る。このとき、その予約の開始時刻は現在時刻（秒を切り捨て）に変更される。変更後の長さにも上限（RSV-6）を適用する                                                                           |
| RSV-16 | 予約の長さが猶予より短い場合、利用開始の操作ができるのは終了時刻までとし、終了時刻に「無断不使用」となる                                                                                                                                                                                                                  |
| RSV-17 | 予約がなくても、空いている機器（RSV-20）はその場で使い始められる。このとき終了時刻を入力し、現在時刻（秒を切り捨て）から終了時刻までを確保した「利用中」の予約として扱う。RSV-3、RSV-19、長さの上限（RSV-6）、先着順の対象となり、システム上に記録される。件数の上限（RSV-4）には数えない（時間帯を変更した後も数えない） |
| RSV-18 | 自分の利用中の予約について、利用終了の操作ができる。終了時刻は操作した時刻（秒を切り捨て）になり、「終了」となる                                                                                                                                                                                                          |
| RSV-19 | 利用を終えた時間帯は解放される。終了の操作を忘れても、終了時刻を過ぎれば「終了」となり解放される                                                                                                                                                                                                                          |
| RSV-20 | 機器が「空いている」とは、現在時刻を含む確保済みの時間帯がないことをいう                                                                                                                                                                                                                                                  |

### 5.5 自動で起きる変化と同時操作

| ID     | 要件                                                                                                                                                                                                                                                                                                                                                          |
| ------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| RSV-21 | 時間帯の解放（RSV-13、RSV-16、RSV-19）は、誰も操作していなくても、次に誰かが見たり操作したりしたときには正しく反映されている。自動で起きた状態の変化の時刻は、反映された時刻ではなく、ルール上の時刻（RSV-13は猶予の終わり、RSV-16とRSV-19は終了時刻）として記録する                                                                                          |
| RSV-22 | 自動で起きる状態の変化の結果は、ルール上の時刻の順に起きたものとして定まる。あらゆる操作（利用者の操作、管理者の操作、数値の変更）は、それより前の時刻の変化には影響しない。同じ時刻では、自動の変化が操作より先に起きる                                                                                                                                      |
| RSV-23 | ほぼ同時に行われた操作は、いずれかの順に1つずつ行われたものとして扱う。その結果は、MNG-2（利用中の予約がある機器は削除できない）、RSV-3、RSV-4、最後の1人の管理者を削除できないこと（ADM-2）、機器の名前と管理者のIDが重複しないこと（MNG-1、ADM-2）に反しない。確保に限らず、時間帯を広げる操作（RSV-9、RSV-10、RSV-14、RSV-17）と管理者の操作にも当てはまる |
| RSV-24 | 予約のルールは、利用者側の操作（画面の改ざん、画面を経由しない直接のデータ操作など）によって回避できない。外部の者に対する多層防御として、ルールの判定はサーバ側で行う                                                                                                                                                                                        |

### 5.6 ルールに使う数値

| ID     | 要件                                                                                                                                                                                                                                   |
| ------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| RSV-25 | 管理者は、下の表の数値を運用しながら変更できる。すべて全機器で共通の値とする。数値を変更しても、変更より前に起きた状態の変化とその記録は変わらない。すでに確保された予約は、数値の変更によって取り消されない                           |
| RSV-26 | 予約の猶予の長さは、その予約の開始時刻の時点で有効な値による。開始時刻を過ぎた予約の猶予は、その後に数値を変更しても変わらない。数値の変更は、秒を切り捨てた現在時刻から有効とする。開始時刻がその時刻と同じ予約には、変更後の値を使う |

| 項目                                           | 条件              | 初期値           |
| ---------------------------------------------- | ----------------- | ---------------- |
| 1人が同時に確保できる予約の件数の上限（RSV-4） | 1以上の整数（件） | 3件              |
| 利用開始の猶予（RSV-13）                       | 1以上の整数（分） | 15分             |
| 1件の予約の長さの上限（RSV-6）                 | 1以上の整数（分） | 24時間（1440分） |

## 7. 管理

管理者の機能のうち、アカウントと共有された情報はADM-2・ADM-3、数値の変更はRSV-25による。

| ID    | 要件                                                                                                                                                                                                                                                                                                                                                               |
| ----- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| MNG-1 | 管理者は機器を追加・変更・削除できる。機器は名前を持ち、種類は持たない。名前は、前後の空白を除いて1文字以上（上限は設計で定める）とし、現にある機器どうしで重複しない。削除した機器の名前は再び使える。予約や記録には、機器の現在の名前（削除した機器は、削除の時点の名前）を表示する                                                                              |
| MNG-2 | 利用中の予約がある機器は削除できない。機器を削除すると、その機器の予約済の予約は「管理者による取消」（原因は「機器の削除」）となる                                                                                                                                                                                                                                 |
| MNG-3 | 管理者は、予約済の予約を取り消し（「管理者による取消」）、利用中の予約を終了させられる（「管理者による終了」。終了時刻は操作した時刻を秒で切り捨てたもの）。その対象を選ぶために、管理者は、機器ごとに予約済・利用中の予約を、利用者（生徒か教員かの区別、学籍番号、名前）とともに確認できる。管理者の表示では学籍番号を見せる（名前は重複しうるので、識別に要る） |
| MNG-4 | v0.1.0 では、機器が使えなくなった場合、管理者がMNG-3によって予約を取り消し、利用を終了させて対応する。その後の新しい予約と予約なしの利用を止める手段は、機器の削除のほかにない（機器を一時的に使えなくする機能は、FUT-5のメンテナンスとして後から加える）。これは承知のうえの制約である                                                                            |

## 8. 記録・セキュリティ・非機能要件

### 8.1 記録

| ID    | 要件                                                                                                                                                                                                                                                                                                                                                                                                               |
| ----- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| LOG-1 | 誰が・いつ・何をしたかを記録し、トラブルの際に追跡できる（本人確認をしないため）。v0.1.0 の時点から記録する。利用者の名前・期生の置き換え（USR-7）も記録する                                                                                                                                                                                                                                                       |
| LOG-2 | 削除したデータ（機器、管理者のアカウントなど）も、記録としては残す                                                                                                                                                                                                                                                                                                                                                 |
| LOG-3 | 予約の状態の変化と時間帯の変更（RSV-9〜RSV-11、RSV-15による開始時刻の変更を含む）を、誰の操作によるか（自動の場合は自動であること）とともに記録する。「取消」「無断不使用」「管理者による取消」は互いに区別し、「終了」と「管理者による終了」も区別する。「管理者による取消」と「管理者による終了」は原因を区別して記録する。v0.1.0 での原因は、取消が「管理者の操作」「機器の削除」、終了が「管理者の操作」である |
| LOG-4 | 管理者の操作（ADM-2、ADM-3、MNG-1〜MNG-3、RSV-25。機器の名前の変更を含む）を、操作した管理者のIDとともに記録する。管理者の認証の成功と失敗も記録する。失敗の記録は、外部からの試行によって容量を使い切られない形で持つ（方法は設計で定める）。失敗の記録に限り、まとめる、または古いものから消すことがある。記録には、パスワードと共有された情報の値そのものを含めない（SEC-4）                                    |
| LOG-5 | 記録に限らず、データは基本的に消さない。自動で消すこともしない（LOG-4の失敗の記録は例外）                                                                                                                                                                                                                                                                                                                          |
| LOG-6 | v0.1.0 では、記録を確認する画面は作らない。記録は、基盤の管理機能など、システムの外から確認する。記録は、後から絞り込んで確認できる形で持つ（FUT-4）                                                                                                                                                                                                                                                               |

| ID    | 要件                                                                                                                                                                                                                                                                                                                                                                                                                   |
| ----- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| SEC-1 | 利用者が入力した内容によって、他の利用者の端末で意図しない動作が起きない                                                                                                                                                                                                                                                                                                                                               |
| SEC-2 | 通信は暗号化する                                                                                                                                                                                                                                                                                                                                                                                                       |

## 9. 将来の変更に備える条件

v0.1.0 では実装しないが、基盤の選定と設計はこれらを作り直しなしで受け入れられるものとする。

### 9.1 公開までに加える機能・品質で、基盤と設計が満たせる必要があるもの

| ID    | 内容                                                                                                                    |
| ----- | ----------------------------------------------------------------------------------------------------------------------- |
| FUT-1 | システムが使えないときに、使えないことと、その間は予約なしで機器を使ってよいことが利用者にわかる                        |
| FUT-2 | 管理者が、無料の範囲に対する使用量を把握でき、残りが少なくなったときに警告を受ける                                      |
| FUT-3 | 1日に1回以上データの控えを取り、失われるのは直近24時間以内の分にとどまる。控えは6週間利用がない間も取られる。復元できる |
| FUT-4 | 管理者が、記録を機器・利用者（USR-4）・期間で絞り込んで確認できる。v0.1.0 の記録は、これを後から加えられる形で持つ      |

### 9.2 メンテナンス機能（公開までに加える）による変更

| ID    | 内容                                                                                 |
| ----- | ------------------------------------------------------------------------------------ |
| FUT-5 | 機器を一時的に使えなくする機能（メンテナンス）が後から加わる。そのとき次の変更が入る |

- 「空いている」の定義（RSV-20）に「メンテナンス中でないこと」が加わる
- RSV-13の判定に例外が加わり、猶予を開始時刻以外の時点（メンテナンスの終了）から数える場合が生じる
- 「管理者による取消」「管理者による終了」が、管理者の操作なしに自動で起きる
- 利用開始の操作（RSV-15の前倒しを含む）を断る条件が増える
- 自動で起きる変化の順序（RSV-22）に、メンテナンスの開始が加わる（同じ時刻では、時間帯の解放がメンテナンスの開始より先）
- 「管理者による取消」「管理者による終了」の原因（LOG-3）に、「メンテナンス」が加わる

## 10. v0.1.0 に含めないもの

実装しないこと。ただし9章の条件は満たすこと。

- 公開まで：端末に入力内容を覚えさせる機能、誰として操作しているかの表示と名前の上書き前の確認、入力内容が全員に見えることの明示、利用者・管理者の自己紹介、全機器の空きの一覧、機器を特定して直接開く機能、確保を解かれた自分の予約の確認、猶予と終了時刻までの残りの表示、メンテナンス、管理者自身のパスワード・表示用の名前の変更、機器の削除と共有された情報の変更の影響範囲の事前表示、機器の順番、記録の確認画面（絞り込みを含む）、使いやすさの検証（説明なしでの試用）、状態の区別を色だけに頼らないこと、停止中の周知（FUT-1の実装）、使用量の把握と警告（FUT-2の実装）、データの控え（FUT-3の実装）、構成・ルール・運用手順の文書化
- 公開の後：記録のファイル出力、記録の削除、情報の掲載（お知らせ、利用者による作品の紹介など）、機器の説明（Markdown・画像）、本人への通知
- 範囲外：機器の利用講習、材料（フィラメントなど）の管理、利用者への通知、無断不使用などに対するペナルティ
